# Ona mutation inventory

Snapshot: 2026-10-07; branch `refactor/backend`; HEAD `03a745f`. Current source map, including migration 077 added in this working tree. No hosted database changes or endpoints invoked.

## Scope and reading rules

This is a static source inventory of job and money mutations, including HTTP handlers, browser writes, server persistence helpers, RPCs, and scheduler/operator entry points. All 175 API route files are indexed below, including reads and aliased exports. An HTTP `GET` is not assumed to be read-only.

The four requested searches were expanded to handle multiline Supabase chains, actual table names (`payments`, `payout_transfer_ledger`, `credit_wallets`, `credit_transactions`, `cashout_requests`), RPC calls, admin routes, and scripts. A search for a table literally named `escrow` would miss the live job escrow ledger, which is `payments`.

**Evidence limits:** source checks are not an audit of deployed policies, secrets, migrations, middleware configuration, or provider behavior. “Browser bypass” means bypass of the API/state-machine checks, not absence of database authorization. Each route's automated evidence lists guard calls found anywhere in its file; it does not mean every method executes every listed check. Conditional paths are explained in the reviewed tables. The imported-module table candidates in the complete route index deliberately over-approximate: they are navigation hints, not a claim that all writes occur for a particular request.

## Findings that affect safe changes

1. **Critical browser write paths removed in dev; database lockdown added here:** Orders status uses the transition API, identity submissions use verification APIs, and presence fallback uses a typed allow-list. Migration 077 revokes protected table writes and adds guard triggers against future blanket regrants. It is present in this branch but has **not been applied to the hosted database**. Existing RLS still governs allowed Pro presence updates.
2. **The helper named `isJobParty` is broader than its name:** it returns true for any caller when job status is `searching` or `negotiating`. Some routes additionally bind actual actor/side; the helper alone is not an ownership guarantee. [source](../src/lib/server/auth-utils.ts#L165)
3. **Reads can mutate:** `getJob` reconciles gateway payment, recovers payout state and expires jobs. Changing it affects route reads, transitions and other server callers.
4. **`expire-stale` authorization is partial:** only `expireOverdueBookedJobs` is inside the `authorized` condition; unaccepted-job sweep, zombie reset, pairing/scheduled dispatch, and payout retry run afterwards regardless. A rejected credential does not prevent all maintenance mutations. [source](../src/app/api/jobs/expire-stale/route.ts#L104)
5. **Money retry authorization varies:** cashout verify is open without configured secret; payout retry has no-secret User-Agent/open-cron branches. Deployment environment decides whether these branches are reachable.
6. **Separate money ledgers:** job escrow uses `payments`; payouts use `payout_transfer_ledger`; shop uses `shop_payments`; Express uses `ona_express_payments`; referral/cashout uses credit wallets/transactions and cashout requests. A change in one ledger is not automatically reflected in the others.
7. **Direct identity/availability writes are adjacent mutation paths:** identity submission now uses APIs; Go Live fallback still directly updates allowed Pro presence fields, influencing discovery. They are listed below even though not direct money ledger writes.
8. **Database schedulers and operator scripts are additional entry points:** Vercel is not the only scheduler; SQL migration 047 defined `pairing_sweep`, migration 048 retires its schedule, and migration 067 configures HTTP payout retry. Applied scheduler configuration is unverified. No maintenance script was executed.
