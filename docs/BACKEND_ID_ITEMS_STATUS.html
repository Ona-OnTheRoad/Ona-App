ONA-ID-101

SMS OTP with provider failover

Partly built
P0Phone OTPSheet: In Progress

Real SMS is sent through one provider (Africa's Talking) in src/lib/server/africastalking.ts. There is no second provider and no failover.

  • Demo code in production. The code 336699 is accepted in production unless OTP_DEMO_MODE or NEXT_PUBLIC_OTP_DEMO_MODE is exactly false, with neither set to true (src/lib/auth/demo-otp.ts).

ONA-ID-203

Live NIN lookup with cached fallback

Partly built
P0Government IDSheet: Blocked

A live lookup exists in src/lib/server/prembly.ts behind /api/verify/nin. There is no cache and no fallback.

  • Format-only pass. With no PREMBLY_API_KEY set, any 11-digit number that is not all the same digit comes back as verified.
  • Open endpoint. The route handler has no sign-in or rate-limit check of its own. Whether middleware covers it was not checked.
  • Result not kept. The lookup result is only used in the browser during signup. src/app/api/auth/signup/route.ts (line 682) sets nin_verified from the number being 11 digits long.
ONA-ID-205

BVN identity match for payouts

Partly built
P0Government IDSheet: In Progress

A BVN lookup exists behind /api/verify/bvn, but the name it returns is never compared with the profile or the bank account. bvn_verified is set by admin Tier 2 approval when a BVN is on file.

  • No identity match. The core of this item, matching the BVN holder to the pro, is missing.
  • NIN copied into BVN. The nin submission in src/app/api/verify/pro-id/route.ts writes the same number into both the NIN and BVN fields, so "BVN on file" can be true when only a NIN was given.
  • Same three bugs as ONA-ID-203. Format-only pass, open endpoint and result not kept all apply to the BVN route too.
